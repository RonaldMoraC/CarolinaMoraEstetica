## Qué falta desarrollar realmente

### 1. Núcleo transaccional de reservas y agenda
Este es el bloque más importante. La documentación lo marca como el corazón del sistema, y todavía es donde más se ve la brecha entre lo planeado y lo implementado.

Falta:
- Lógica real de mallas horarias y excepciones del personal
- Cálculo de disponibilidad de horarios
- Validación de conflictos y sobrebooking
- Reprogramación, cancelación con reglas de negocio, check-in y cierre de servicio
- Implementación de bloqueos transaccionales y manejo de concurrencia

Esto encaja directamente con las skills de concurrencia, zona horaria y diseño defensivo.

### 2. Módulo de facturación y POS
La arquitectura lo define como obligatorio, pero sigue siendo un área pendiente de materialización.

Falta:
- Entidades y casos de uso de pagos
- Flujo de facturación
- Apertura/cierre de caja
- Reembolsos y reglas de inmutabilidad financiera
- Idempotencia para evitar cobros duplicados

Aquí es clave la skill de idempotencia y la de arquitectura financiera robusta.

### 3. Integración con WhatsApp y worker de colas
Este módulo está claramente planteado en la documentación, pero aún no está en un estado operativo.

Falta:
- Webhook de WhatsApp
- Validación de firma y verificación de handshake
- Parser de mensajes
- Máquina de estados conversacionales
- Cola de notificaciones y worker por lotes
- Reintentos con respaldo exponencial
- Manejo de duplicados y procesamiento asíncrono

Esto está muy alineado con las skills de webhooks, resiliencia y workers para hosting compartido.

### 4. PWA offline-first
La documentación lo deja como una necesidad clara para la experiencia del cliente.

Falta:
- Service worker con estrategia real de caché
- Persistencia local con IndexedDB
- Cola de sincronización para acciones offline
- Sincronización automática al recuperar conectividad

Esta es una de las áreas más visibles para el usuario final.

### 5. Seguridad y trazabilidad
Aunque la arquitectura ya lo menciona, todavía hay trabajo concreto para que sea robusto.

Falta:
- Implementación real de encriptación de datos sensibles
- Auditoría automática de mutaciones críticas
- Manejo estandarizado de errores en formato de problema
- Sanitización y uso consistente de prepared statements
- Logging estructurado y seguro

Esto está muy alineado con las skills de seguridad, auditoría y manejo de errores.

### 6. Pruebas y calidad
Es uno de los puntos más débiles del proyecto.

Falta:
- Pruebas unitarias de dominio y casos de uso
- Pruebas de integración con base de datos
- Fixtures y entorno aislado
- Validación automática de reglas de negocio
